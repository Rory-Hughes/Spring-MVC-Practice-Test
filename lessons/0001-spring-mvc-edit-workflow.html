Follow one library checkout from a row in a list to a prefilled edit form, through validation and back to the database.

These excerpts belong to an example library app. Assume a supplied Checkout entity with id, borrower and loanDays properties and a CheckoutRepository extending JpaRepository<Checkout, Long>. Our edit form changes the borrower and loan length. Use the same steps with the names and rules from the practice exam.

List GET → row link → edit GET → prefilled form → edit POST
Invalid POST → same form with errors
Valid POST → database update → redirect → list GET

1. Build GET and POST handlers

Write down the HTTP method, route, model keys and return value for each handler. Put the common path on the class with @RequestMapping. The method mapping adds the rest of the path. @PathVariable reads the selected row ID, and Model passes named values to the template.

@Controller
@RequestMapping("/checkouts")
class CheckoutController {
    private final CheckoutService service;

    CheckoutController(CheckoutService service) {
        this.service = service;
    }

    @GetMapping
    String list(Model model) {
        model.addAttribute("checkouts", service.findAll());
        return "checkouts/list";
    }

    @GetMapping("/{id}/edit")
    String edit(@PathVariable("id") long id, Model model) {
        Checkout checkout = service.require(id);
        CheckoutForm form = new CheckoutForm();
        form.setBorrower(checkout.getBorrower());
        form.setLoanDays(checkout.getLoanDays());
        model.addAttribute("checkoutForm", form);
        model.addAttribute("checkoutId", id);
        return "checkouts/edit";
    }

    @PostMapping("/{id}/edit")
    String update(@PathVariable("id") long id,
                  @Valid @ModelAttribute("checkoutForm") CheckoutForm form,
                  BindingResult errors, Model model) {
        if (errors.hasErrors()) {
            service.require(id);
            model.addAttribute("checkoutId", id);
            return "checkouts/edit";
        }

        service.update(id, form);
        return "redirect:/checkouts";
    }
}
  1. List GET. Read the collection, put it in the model, then return the logical view name. With the standard Thymeleaf setup, checkouts/list maps to templates/checkouts/list.html.
  2. Edit GET. Load the selected row and copy its editable values into the form. Add the form and the ID to the model.
  3. Edit POST. Spring binds request fields to the named form. When errors exist, retain that bound object and restore any additional data the template needs, such as the ID and dropdown options. On success, redirect: tells the browser to make a new GET, so refreshing reloads the list.

2. Validate input and show field errors

Translate each rule into a constraint. Import annotations from jakarta.validation.constraints and import jakarta.validation.Valid in the controller. The starter includes the validation dependency.

public class CheckoutForm {
    @NotBlank(message = "Enter the borrower's name.")
    @Size(max = 50, message = "Use 50 characters or fewer.")
    private String borrower;

    @NotNull(message = "Enter the loan length.")
    @Min(value = 1, message = "A loan must be at least one day.")
    @Max(value = 21, message = "A loan can be at most 21 days.")
    private Integer loanDays;

    // Provide public getters and setters for both fields.
}
  1. @NotBlank rejects empty or whitespace-only strings. @Size bounds length. Use both for required text with a length limit.
  2. Integer can hold null, which lets @NotNull catch a blank number. @Min and @Max check numeric boundaries. Text that cannot convert to an integer produces a binding error.
  3. Put BindingResult immediately after the validated form parameter. Call hasErrors() before the service update. A failed validation should leave the stored row unchanged.
  4. Inside the form, th:errors displays a field's messages. #fields.hasErrors('borrower') can guard the error element, and th:errorclass adds a CSS class to the input when it has errors.
<input type="text" th:field="*{borrower}" th:errorclass="invalid">
<p th:if="${#fields.hasErrors('borrower')}" th:errors="*{borrower}"></p>

Try a blank borrower and loan length 0. Then correct the borrower and enter 21. Predict which request saves and which page displays each message.

3. Display a collection in a table

Put the headings in <thead>. Inside <tbody>, repeat the entire row with th:each. The part before the colon names the current record. The part after it names the collection that the controller put in Model.

<table>
    <thead>
        <tr><th>Borrower</th><th>Loan days</th><th>Action</th></tr>
    </thead>
    <tbody>
        <tr th:each="checkout : ${checkouts}">
            <td th:text="${checkout.borrower}"></td>
            <td th:text="${checkout.loanDays}"></td>
            <td><a th:href="@{/checkouts/{id}/edit(id=${checkout.id})}">Edit</a></td>
        </tr>
    </tbody>
</table>

Compare the model key checkouts with the collection expression. Open two links and confirm that their IDs differ. A blank table can mean the service returned an empty list or the template used the wrong model key.

4. Build a form that edits an existing row

Set th:object to the form model key. Inside the form, *{...} refers to a property of that object. For these inputs, th:field sets the submitted field names, input IDs and displayed values. The action URL uses the ID provided by the controller.

<form method="post" novalidate th:object="${checkoutForm}"
      th:action="@{/checkouts/{id}/edit(id=${checkoutId})}">
    <label for="borrower">Borrower</label>
    <input type="text" th:field="*{borrower}" th:errorclass="invalid">
    <p th:errors="*{borrower}"></p>

    <label for="loanDays">Loan days</label>
    <input type="text" inputmode="numeric" th:field="*{loanDays}" th:errorclass="invalid">
    <p th:errors="*{loanDays}"></p>

    <button type="submit">Save</button>
    <a th:href="@{/checkouts}">Cancel</a>
</form>

novalidate lets you exercise server-side validation in the browser. A text input with inputmode="numeric" suggests a numeric keyboard and lets the form show rejected text again after a conversion error. Open an edit page, check both prefilled values, then submit an invalid value. Look for the entered value, its error and the same form destination.

5. Update an existing database record

Use the URL ID to look up the row. Handle a missing record, copy the fields the user is allowed to edit, and save the loaded entity with its identity intact. The controller calls this service method only when binding and validation succeed.

@Service
class CheckoutService {
    private final CheckoutRepository repository;

    CheckoutService(CheckoutRepository repository) {
        this.repository = repository;
    }

    public List<Checkout> findAll() {
        return repository.findAll();
    }

    public Checkout require(long id) {
        return repository.findById(id).orElseThrow(() ->
            new ResponseStatusException(HttpStatus.NOT_FOUND, "Checkout not found"));
    }

    @Transactional
    public void update(long id, CheckoutForm form) {
        Checkout existing = require(id);
        existing.setBorrower(form.getBorrower());
        existing.setLoanDays(form.getLoanDays());
        repository.save(existing);
    }
}

Test with two rows. Change one, then reload the list and reopen both edit pages. Verify the changed values, the untouched row and the same row count. Request a missing ID to check the failure path.
